# MVP 개발 계획

> MVP = ARCHITECTURE.md 로드맵의 **Phase 1(수집) + Phase 2(매출·중복 소거)**를 로컬에서 끝까지 동작시키는 것.
> 배포는 범위 밖입니다(대행사 계정·도메인 수령 후 진행).

## 완료 기준

1. 테스트 사이트에서 트래커 이벤트 수집 → ClickHouse 적재 → 대시보드 개요·채널·페이지·이벤트·실시간 화면에 실제 데이터 표시
2. S2S 주문 API(확정·취소·부분환불) → 주문 상태 투영 → 기여 연산 잡 → **실제 매출(중복 소거) 화면**에 실제 데이터 표시
3. 매뉴얼 1.A 시나리오(18:10 네이버 → 18:40 메타 → 18:45 ORD-9901 100,000원)를 E2E 테스트로 재현: 합산 200,000 / 실제 100,000 / 중복률 50% / Last-Click 메타 100,000 / Linear 50,000+50,000
4. 로그인, 광고주·프로젝트 생성, 스니펫·비밀 키 발급, 수집 설정 변경이 대시보드에서 가능
5. `make lint test` 통과, 코드리뷰·리팩토링 리뷰 지적사항 반영

## 개발 원칙: TDD

각 작업은 **실패하는 테스트를 먼저 커밋**(`test: ...`)한 뒤 구현을 커밋(`feat: ...`)합니다. 테스트는 아래 분류를 모두 검토하고, 해당하는 것은 빠짐없이 작성합니다.

| 분류 | 예 |
|---|---|
| 해피 케이스 | 정상 입력 → 기대 결과 |
| 멱등성 | 같은 요청·잡을 두 번 실행해도 결과가 같음 (재전송, 웹훅 중복, 잡 재실행) |
| 경계값·엣지 | 0, 음수, 최댓값, 빈 값, lookback 경계 시각, 유니코드, 매우 긴 값, 대량 입력 |
| 희귀 케이스 | 순서 뒤바뀐 이벤트(취소가 확정보다 먼저), 늦게 도착한 데이터, 시계 오차, 같은 ms 이벤트 |
| 외부 공격 | 인증 우회, 다른 테넌트 데이터 접근, SQL·헤더 인젝션, 과대 페이로드, 키 추측, 서명 위조·재사용, 세션 고정 |
| 장애·복구 | DB 일시 장애, 부분 실패, 재시도 |

통합 테스트는 `analytics-testkit::TestDb`로 테스트마다 격리된 Postgres·ClickHouse DB를 씁니다 (`make up` 필요).

## 작업 패키지

| ID | 패키지 | 주요 산출물 | 의존 |
|---|---|---|---|
| WP1 | S2S 주문 | `core::orders`(검증·상태 투영), 비밀 키 발급·검증, ingest `/v1/orders`·`/v1/orders:batch`·`/internal/orders`, `order_events`/`orders` 적재, 클라이언트 purchase → 주문 투영 | Phase 0 |
| WP2 | 기여 연산 잡 | `jobs attribution`(증분·전체), `jobs conservation-check`, identity 확장, 채널 규칙 소급, 취소 시 삭제 표시 | Phase 0 (orders 테이블 계약) |
| WP3 | API 인증·관리 | 로그인·세션·로그아웃, 관리자 부트스트랩, 광고주·프로젝트·허용 도메인·설정·채널 규칙·비밀 키 관리 API, 권한·테넌트 격리 미들웨어 | Phase 0 |
| WP4 | 리포트 쿼리 | `analytics-ch::reports`: 개요·시계열·채널·페이지·이벤트·실시간·전자상거래 퍼널·실제 매출 리포트, `core::dto::reports` | Phase 0 |
| WP5 | 엣지 Worker | `edge/worker`(workers-rs): `/v1/collect`·`/v1/config`·`/v1/orders` → HMAC 서명 후 원점 전달, 실패 시 Queue | Phase 0 |
| WP6 | 리포트 API 연결 | api에 WP4 리포트 엔드포인트 연결 | WP3, WP4 |
| WP7 | 대시보드 연동 | 로그인 화면, 광고주·프로젝트 전환, 모든 화면 실데이터, 설정 화면 저장 | WP3, WP6 |
| WP8 | MVP E2E | 매뉴얼 1.A 시나리오 E2E, 문서 갱신 | 전부 |

진행 순서: WP1~WP5 병렬 → 코드리뷰·리팩토링 리뷰 → 반영 → WP6·WP7 → 리뷰 → 반영 → WP8 → 최종 리뷰.
